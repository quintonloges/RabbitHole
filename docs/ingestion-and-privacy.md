# Ingestion, privacy and limits

RabbitHole stores one administrator's collection on the chosen machine/server, with a separate public catalog of eligible external metadata and bounded source excerpts. There are no visitor accounts, analytics, advertisements or external managed database dependencies. Uploaded files/text, notes, history, trails, practice, settings, subscriptions and AI results are private. Internet egress comes from configured source refreshes, explicitly requested research/URL lookups, opted-in media players, explicitly invoked AI actions and configured encrypted backups. Fonts and visual assets do not require a third-party CDN.

Publication is persistent and separate from personal state. Credential-bearing/private URLs and document-derived records, including aliases and stale section references, are excluded before public search/counts/facets/sitemap. Public requests are read-only and do not record learning activity. Public related results use metadata only. HTTPS cookie sessions and CSRF protect all existing APIs, exports, files/ranges and writes; there is no public setup wizard. See [public hosting](public-hosting.md) for the complete boundary and operational commands.

`Ingestion:Paused` or the administrator's `ingestionPaused` setting stops scheduled refreshes and provider test/import/search operations without changing `Sources.Enabled`, cursors or topic assignments. A current in-flight request may finish; consistent backups stop the API before taking a database/files pair. Staging forces pause in server configuration, independently of restored user preferences.

## Source handling

- RSS/Atom supplies actual titles, authors, dates, excerpts and full feed text when present. HTML is reduced to plain text. A missing publication date stays unknown. Malformed feeds fail independently.
- OpenAlex and arXiv search/watch results retain paper metadata and abstracts when available, not invented full text. API budgets/authentication can change; inspect actual health rather than assume availability. RabbitHole acknowledges arXiv for use of its open-access interoperability API.
  OpenAlex watches use newest-first cursor pages and a seven-day publication-date overlap; the initial seed is a finite newest selection. Cursor continuation beyond the first page requires an API key under the current provider policy. Failed continuation is visible and does not advance the checkpoint. Older delayed indexing is outside that overlap; use explicit research search when needed. See the official [sorting](https://help.openalex.org/api/sorting/), [filtering](https://help.openalex.org/api/filtering/) and [paging](https://help.openalex.org/api/paging/) documentation. arXiv's supplied summary is stored as a bounded provider abstract, separately from its short excerpt.
- YouTube uses canonical video IDs, official oEmbed metadata and public channel feeds. Video playback is through a supported player, loaded only when requested. Arbitrary captions/transcripts are not fetched. The official captions download API requires owner/editor permissions.
- SoundCloud uses official oEmbed metadata and an allowlisted widget. Track/playlist import does not promise global track discovery or downloads. Artist/music topic preferences are editable taste terms, not fabricated playable records.
- Manual websites are metadata/excerpt imports, with robots checks and honest link-only fallback. Full article bodies are not scraped to evade licensing, paywalls or access controls.
- A selected feed entry can enrich a URL import using `feedUrl`; it must match an actual entry returned by the safe, size-limited RSS/Atom fetcher. No subscription or unrelated feed entries are created. Publication/author metadata is source-supplied, and missing dates remain unknown. Source CSS/scripts/comments are removed before plain-text display.
- OpenAlex watches without a key fetch a bounded newest-page sample and may miss results in busy queries. A key enables cursor continuation. Watch queries use titles/abstracts (`title:` for titles only), a two-year initial window, and a seven-day overlap. These controls concern topical fit and retrieval size, not editorial credibility.
- Local PDF/EPUB originals stay on the private upload volume. EPUB chapter order comes from the real spine; EPUB 3 navigation and EPUB 2 NCX labels target actual file/fragment boundaries, including multiple chapters inside one XHTML file. Untitled text uses its available heading or filename, and unavailable anchors or malformed markup retain file text with a warning. Empty/image-only entries remain in the original. PDF pages are always retained; real bookmarks and user page ranges supplement them and appear before the separate page list. Rebuild sections preserves replaced extractions and their notes/progress under Previous extraction. Complex layout may extract imperfectly. OCR, DRM removal and EPUB embedded media execution are not implemented.

## URL and parser boundaries

The general fetcher rejects non-HTTP(S), credentials in URLs, unexpected ports, private/reserved addresses and local hostnames. DNS is checked and the socket connects to a checked IP; every redirect is revalidated. Redirects, response length, MIME and request duration are bounded. HTTP errors and retry timing are recorded without provider credentials or response bodies in logs. It does not use arbitrary proxy environment variables to bypass checks.

External HTML/Markdown is never executed. Original links use safe schemes and new-tab isolation. Provider iframe origins are allowlisted and playback requires a user click. Library originals are served with `nosniff` and a sandbox policy. Browser PDF rendering is the browser's built-in viewer; EPUB files download for an external reader when original viewing is selected.

Uploads are limited to 50 MiB. EPUB limits cover entry count, declared expanded size, compression ratio, unsafe names, XML entities and encrypted packages. PDFs are limited to 2,000 pages, extracted text/output size and an isolated worker deadline/heap. Parsing failure preserves an original-file fallback. The container also has a memory limit. This is defensive processing of personal files, not a public multi-user upload service.

## Secrets, backup and AI

Environment values are not exposed in the frontend, logs or export. Status endpoints expose only whether optional providers are configured. Keep development's `.env`, the private production snapshot in `.local/production/`, uploads and backups out of version control. The production snapshot preserves effective container settings and may contain provider keys; back it up privately, separately from the database/files backup, and do not share its rendered Compose configuration. Development starts with separate credentials and empty data. A backup/export contains personal notes and potentially private copyrighted book text; it is for personal recovery, not publication.

Export uses explicit field projections. Credential parameters are removed from source/item/origin URLs, URL-shaped identifiers, recursive provider metadata, encoded nested player URLs, fragments and userinfo. Malformed or oversized provider metadata is omitted from the export; stored originals are unchanged. Database backups retain original private data and credentials embedded in configured URLs, so protect them separately from the sanitized interchange export.

AI sends only explicitly selected bounded passages and a user response to the configured endpoint. Set a trusted local endpoint and `AI_ALLOW_LOCAL=true` to use a local compatible service. Local AI networking is intentionally separate from arbitrary public-web fetching. No source text can cause the model to execute application actions. Model prose is still fallible; structural validation and actual references are not a guarantee of factual correctness.

## Intentional product boundaries

Unconventional interests are not assigned credibility scores or corrective labels. Personal topic/source controls determine discovery. Counterarguments are a requested exploration action, never an automatic intervention. Transient curiosity does not mutate topic weights. The finite edition is a default pace; more items remain accessible on demand.

Optional Semantic Scholar enrichment, authenticated YouTube search, global SoundCloud search, OCR, automatic transcript ingestion and automatic JSON archive merge-restore are not implemented. Their working alternatives are arXiv/OpenAlex, channel feeds/known URLs, official embeds, original-file viewing, source text and database/files backup restore. There is no mandatory external account or AI provider.
